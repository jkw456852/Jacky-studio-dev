# 原子能力节点 UI 信息架构与极简设计规范

最后更新：2026-05-12

关联：

---

## 1. 页面目标

把“原子能力”从内部能力清单，变成普通用户也能看懂、能直接使用的画板节点。

不是做一个开发者后台，不是做一堆解释面板，而是做成：
- 找得到
- 看得懂
- 拖得动
- 配得明白
- 跑得起来
- 结果看得清

---

## 2. 用户主任务

用户进入工作区后，最核心的任务只有 3 个：

1. 找到要用的能力
2. 把能力放到画板里
3. 填最少必要信息并运行

次级任务：
- 看运行状态
- 看结果
- 把多个节点连起来
- 保存为 recipe

---

## 3. 功能清单

### 3.1 一级功能
- 原子能力节点库
- 搜索能力
- 按类别浏览能力
- 拖入画板 / 点击加入画板
- 节点基础配置
- 运行节点
- 查看结果
- 查看简洁状态

### 3.2 二级功能
- 查看详细输入 schema
- 查看详细输出 schema
- 查看调试日志
- 查看 capability id
- 查看版本信息
- 保存为 recipe
- 导出分享

### 3.3 不应放在首页或默认态的功能
- 内部 executorRef
- capability compatibilityLevel
- deprecatedIn / introducedIn
- replacedBy 技术说明
- 原始 schema JSON
- 调试级日志全文

这些属于开发/诊断信息，只能进入“高级信息”折叠区，不能默认堆给普通用户。

---

## 4. 信息架构

### 4.1 左侧：原子能力库
只做三件事：
- 搜索
- 分类切换
- 能力卡片列表

### 4.2 中间：画板
只展示节点，不展示大段解释。

### 4.3 右侧：节点配置面板
只展示当前选中节点的：
- 名称
- 一句话用途
- 必填项
- 运行按钮
- 最近结果

### 4.4 底部或二级抽屉：运行详情
用于：
- 错误原因
- 完整日志
- 输入输出详情

默认关闭，不抢主任务注意力。

---

## 5. 页面区块划分

### A. 原子能力库区块
组成：
- 顶部标题
- 搜索框
- 分类 tabs
- 能力列表

### B. 画板节点区块
组成：
- 简洁节点卡片
- 连线
- 选中态
- 运行态

### C. 节点配置区块
组成：
- 节点标题
- 一句话说明
- 表单字段

### D. 结果 / 日志区块
组成：
- 结果摘要
- 失败原因
- 详细日志折叠区

## 6. 低保真线框说明

### 6.1 原子能力库
- 顶部一行标题：`能力库`
- 标题下方一行搜索框
- 再下一行是 4~6 个分类 tab
- 下方是单列卡片列表

每张卡片只保留：
- 名称
- 一句话说明
- 1 个轻量类别标签
- `加入画板` 按钮

禁止：
- 一张卡片里塞 6~10 行说明
- 卡片内再套卡片
- 同时出现 schema、日志、版本、调试说明

### 6.2 画板节点
节点卡片只保留：
- 名称
- 简短状态
- 1 个主动作

例如：
- `商品分析`
- `待填写`
- `运行`

不要在节点上塞满：
- 长段说明
- 多个副标题
- 多个边框区块
- 大片参数正文

### 6.3 配置面板
布局顺序：
1. 标题
2. 一句话说明
3. 表单
4. 主按钮
5. 最近结果
6. 高级信息（折叠）

---

## 7. 文案规范

### 7.1 标题必须像产品，不像代码
用：
- `商品分析`
- `图片生成`
- `换装`
- `网页搜索`

不用：
- `vision.analyze.product`
- `fashion.compose.tryon`
- `research.search.web`

技术 id 只能作为辅助信息放到次级位置。

### 7.2 说明必须是人话
用：
- `分析这张商品图，提取款式、材质和颜色信息。`
- `根据提示词生成图片。`
- `根据服装图和模特图生成试穿效果。`

不用：
- `返回结构化分析信号供 downstream step 消费。`
- `调用统一执行入口并写入 runtime trace。`

### 7.3 按钮文字必须直接
用：
- `加入画板`
- `运行`
- `查看结果`
- `重试`

不用：
- `实例化节点`
- `执行 capability`
- `进入运行时`

---

## 8. 视觉规范

### 8.1 字体层级
- 页面标题：20 / 600
- 区块标题：16 / 600
- 正文：14 / 400
- 辅助说明：12 / 400

同一屏最多 4 档，不再加更多层级。

### 8.2 间距
- 页面边距：24
- 模块间距：24 / 32
- 卡片内边距：16
- 表单项间距：12
- 图标与文字：8

### 8.3 颜色
- 主体：灰白中性色
- 主色：一个低饱和深色或蓝灰色
- 成功 / 错误只做轻提示，不大面积高饱和

### 8.4 圆角和边框
- 圆角统一 12
- 主要用浅边框
- 阴影极轻
- 禁止“大框套小框再套描边框”

---

## 9. 组件规范

### 9.1 原子能力卡片
只允许：
- 一个标题
- 一句说明
- 一个轻标签
- 一个主动作

### 9.2 节点卡片
只允许：
- 标题
- 状态
- 主操作

### 9.3 配置表单
规则：
- 一项一行
- 标签在上，输入框在下
- 必填项清楚但不吓人
- 高级项默认折叠

### 9.4 日志与结果
规则：
- 默认只显示摘要
- 用户点开后再看详细内容
- 不要一上来就铺满整屏日志

---

## 10. 明确禁止的反模式

以下风格本项目禁止再次出现：
- 大框套小框
- 一个区块里同时堆标题、解释、辅助标题、说明、按钮、标签、表单
- 每一项设置都挤在一起
- 多段长文解释直接怼在主界面
- 把内部术语当作用户文案
- 同一层级里出现多个视觉重点
- 复杂边框、厚阴影、重装饰

---

## 11. 原子节点 UI 的最终形态

最终不是只有一个 workflow 面板，而是 3 层同时存在：

### 11.1 原子能力库
给用户挑能力。

### 11.2 原子能力节点
让用户直接把单个能力拖进画板运行。

### 11.3 recipe 生命周期中心
负责导入、测试、发布、分享。

也就是说：
- 原子能力库是“选能力”
- 原子节点是“用能力”
- recipe 面板是“治理能力组合”

三者不是一回事，不能混成一个大杂烩后台。

---

## 12. 前端实现顺序

### 第 1 步
先做原子能力库 UI：
- 搜索
- 分类
- 极简卡片
- 加入画板

### 第 2 步
再做原子节点卡片：
- 统一外观
- 统一状态
- 简洁主操作

### 第 3 步
再做 schema 驱动配置面板：
- 自动渲染输入项
- 区分必填 / 可选
- 高级项折叠

### 第 4 步
最后做单节点执行与结果回写。

---

## 13. 验收标准

满足以下才算通过：
- 第一次看就知道每个能力是干什么的
- 不需要懂内部 id 才能操作
- 没有大段内部说明污染主界面
- 画面留白充足，层级清楚
- 节点卡片轻量，不像后台配置表
- 配置面板不拥挤，不重叠，不堆叠
- 普通用户能在几秒内完成“找到能力 → 加入画板 → 运行”

未通过情形：
- 看起来像开发者后台
- 标题和说明太多
- 大框套小框
- 一屏太挤
- 文案像内部文档
- 看不懂从哪里开始用
